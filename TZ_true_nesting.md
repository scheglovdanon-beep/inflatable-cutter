# ТЗ: True-Shape Nesting (укладка по реальному контуру) вместо bbox

Статус: ПРОТОТИП под флагом `true_nest` (деф. выкл). Рабочие пути не трогаем.

## 1. Текущее состояние (что и где)
Раскладка выбирается в `export_svg.build_layout` (в конце), по флагам конфига:
- `roll_pack` → `pack.nest_roll` — rectpack `MaxRectsBaf` по **bbox** (прямоугольники).
- `print_arrange` → `pack.arrange_print` — ручные колонки «в ряд» (печать).
- `arrange_sides` → `pack.arrange_sides` — ручные колонки.
- `repack` → `pack.repack_layout` — shelf-упаковка по **bbox** (полки).

Все общие упаковщики кладут **ограничивающие прямоугольники** деталей → между вогнутыми
деталями (купольные боковины, трапеции плеча, фигуры перёд/зад) много пустот.

Инфраструктура перемещения деталей уже есть:
- `pack._units_aff(layout)` — список «единиц» с `apply(aff)`: аффинное преобразование детали
  И всех её данных (припуск `seam`, отверстия руки, днище-круг, ножка). Контуры/цвета/подписи
  не меняются — двигается геометрия.
- `pack.nest_shapes` — УЖЕ существующий полигональный нестер (bottom-left по СЕТКЕ), но он
  используется только в печатной нарезке PDF (`export_pdf_grouped._rollpack_svg`), не в основной
  раскладке, и сетка (шаг ~25 мм) оставляет зазоры.

Контуры деталей — это shapely-полигоны в мм (безье/SVG-конвертация НЕ нужна; п.3 плана неактуален).

## 2. Подход (адаптация pyFit)
Референс: `badass-data-science/pyFit-agentic-polygon-nesting` — `nfp.py` (No-Fit Polygon через
Minkowski-сумму на `pyclipper`), `packer.py` (bottom-left по вершинам NFP + углам листа),
`geometry.py` (повороты/площадь). `pyclipper==1.4.0` уже в зависимостях.

Идея NFP: чтобы деталь B не налазила на A, её реф-точка должна лежать ВНЕ внутренности
`NFP(A,B) = A ⊕ (−B)`. Граница NFP = позиции касания. **Вершины NFP** против каждой уложенной
детали = точные кандидатные позиции «впритык / в вогнутость» (а не узлы грубой сетки).

## 3. Реализация (минимальный прототип)
- `src/nest_true.py`:
  - `_nfp_candidates(stationary, moving_pts)` — вершины `pyclipper.MinkowskiSum(−B, A)` (масштаб 1e5).
  - `_place_order(...)` — один прогон bottom-left: для каждой детали перебор поворотов
    `(0,90,180,270)`; кандидаты = вершины NFP против уложенных + пристеночные (x=0, стопка);
    фильтр по границам полосы и допуску пересечения (касание ок), выбор самого левого-нижнего;
    сеточная подстраховка, если NFP пуст. Зазор — `buffer(gap/2)`.
  - `nest_true_shape(shapes, roll_h, gap, rotations, orders)` — пробует НЕСКОЛЬКО порядков
    (площадь/высота/ширина/периметр/макс.сторона) и берёт самый плотный (мин. ширина).
    Интерфейс как у `nest_shapes`: `([(id,Polygon)], roll_h, gap) -> ({id: affine6}, width)`.
- `pack.nest_true_layout(layout, roll_h, gap)` — обёртка: `_units_aff` → `nest_true_shape` →
  `apply(aff)`. Пишет `sheet_w/sheet_h/roll`.
- `export_svg.build_layout`: ветка `if cfg.get("true_nest"):` ПЕРЕД `roll_pack` (приоритетно, деф. выкл).

## 4. Сохранение производственных данных (п.6 плана)
Наружу отдаётся ТОЛЬКО аффин (поворот вокруг 0,0 + сдвиг). `apply(aff)` двигает исходные
shapely-контуры, припуски, центры отверстий. Цвета/подписи/заливки/ключ сборки не трогаются —
они считаются/рисуются по этим же геометриям в рендере. Оригинальные векторы не упрощаются
(упрощённый буфер — только для РАСЧЁТА позиции, в макет не идёт).

## 5. Тест (п.7 плана) — `tests/test_nesting.py`
На реальной раскладке: сравнить `repack_layout` / `nest_roll` / `nest_true_layout`:
- заполнение листа `% = Σ площадь деталей / (sheet_w·sheet_h)`;
- время выполнения;
- геом. корректность: нет пересечений припусков (сверх допуска касания) и выхода за границы.
Критерий: `true_nest` даёт заполнение НЕ ХУЖЕ bbox-путей и без наложений/выходов.
